# 疑案簿 · 微信小游戏版本开发计划 & 版权风险评估

> 版本：v0.1
> 日期：2026-10-31
> 前置状态：Web 版已完成 M1–M5（`packages/puzzle-core` + `apps/web`），线上产物 520KB

## 0. 结论摘要

| 问题 | 结论 |
|------|------|
| 该不该做 | **值得做**。引擎 100% 可复用（纯 TS、零依赖、无 DOM/Node API），只有视图层需要重写 |
| 形态选择 | **微信小游戏（Canvas 2D）**，而非普通小程序。见 §2 选型对比 |
| 工期 | 单人 **6 周**（30 人日，含 1 周缓冲），其中合规备案可与开发并行 |
| 版权风险 | **玩法无风险、名称有明确风险、内容当前低风险**。最大风险不在著作权而在**商标/不正当竞争**与**平台资质（备案/版号）** |
| 上线前置 | IAA 路线（纯广告、不开虚拟支付）**不需要版号**，但需要：小游戏备案（前置审批 10–20 工作日）+ 小程序工信备案 |

## 1. 现状盘点（决定复用边界）

| 资产 | 位置 | 小游戏可复用性 |
|------|------|----------------|
| 推理引擎 | `packages/puzzle-core/src/*.ts` | ✅ 100%。纯 TS，无 `node:*` / DOM 依赖，导出 8 个模块 |
| 生成器入口 | `packages/puzzle-core/src/generator.ts:46` `generatePuzzle(config)` | ✅ 直接调用 |
| 每日题入口 | `packages/puzzle-core/src/generator.ts:228` `dailyPuzzle(dateISO, difficulty)` | ✅ 种子确定，端上生成即可全员同题 |
| 提示引擎 | `packages/puzzle-core/src/humanSolver.ts:204` `getHint(...)` | ✅ 纯计算 |
| 交互/状态 | `apps/web/src/stores/*.ts`（Zustand） | ⚠️ 逻辑可抄、API 不可用（无 React） |
| 视图 | `apps/web/src/components/*`（TSX + Tailwind 4） | ❌ 全部重写（无 DOM、WXSS 不支持 Tailwind 4 的 oklch/color-mix/@property） |
| 持久化 | `localStorage`（Zustand persist） | ❌ 换 `wx.setStorageSync` |
| PWA/Service Worker | `apps/web` | ❌ 无意义，删除 |

**关键结论**：这是「一套引擎 + 两套皮」，不是「跨端改造成本」。UI 约占现有代码量的 60%，但逻辑简单（网格 + 列表 + 弹窗），Canvas 重写可控。

## 2. 形态与技术选型

### 2.1 三条路，选一条

| 方案 | 复用度 | 体验/性能 | 审核风险 | 工期 | 判决 |
|------|--------|-----------|----------|------|------|
| **A. 小游戏 + 自研 Canvas 2D** | 引擎 100%，UI 0% | 好（单 Canvas，网格 ≤ 36 格，无压力） | 低（正规形态） | 6 周 | ✅ **推荐** |
| B. 小游戏 + Cocos Creator | 引擎 100%，UI 用 Cocos | 好，但引擎包 1–2MB、需适配层 | 低 | 7–9 周 | 备选（团队熟悉 Cocos 时） |
| C. 普通小程序（WXML/WXSS） | UI 可部分翻译 | 好 | **高**：小程序一级类目没有「游戏」，用工具/教育类目包装游戏，提审属于典型驳回项 | 4 周 | ❌ 不建议 |
| D. 小程序 web-view 嵌 H5 | 100% | 差（白屏、无法分享、无广告） | **极高**：web-view 需已备案业务域名 + 非个人主体，且被认定为规避审核 | 1 周 | ❌ 否决 |

### 2.2 官方硬约束（已核对微信开放文档）

- **类目**：小游戏账号只有「游戏」一个一级类目，二级类目发布前可改；个人主体**不支持**「文化互动/角色类/牌类」。本作选 **休闲**。
  来源：[类目设置](https://developers.weixin.qq.com/minigame/introduction/guide/type)
- **代码包**：主包 ≤ 4MB，主包 + 分包总计 ≤ 30MB。
  来源：[代码包](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-package)、[分包加载](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/subPackage/useSubPackage)
- **资质**：
  - 走 **IAP（虚拟支付）** → 必须《网络游戏出版物号核发单》（版号）+ 软著。
  - 走 **IAA（纯广告，无虚拟支付）** → **不需要版号**，走「小游戏备案」前置审批；仅当游戏名含英文、或涉及品牌/公众人物合作时才要求软著。
    来源：[资质审核-IAP](https://developers.weixin.qq.com/minigame/introduction/guide/zzsh-iap)、[资质审核-IAA](https://developers.weixin.qq.com/minigame/introduction/guide/zzsh-iaa)
- **备案时长**：平台初审 1–2 工作日，主管部门 10–20 工作日；备案期间**不能改名、不能迁移主体**。
  来源：[小游戏备案](https://developers.weixin.qq.com/minigame/introduction/guide/nrjs)

> 推论：**先把名字定死再提交备案**。名字定了就不能改，改名要重走 10–20 工作日。

## 3. 版权与合规风险评估

### 3.1 风险分级

| # | 风险项 | 现状 | 等级 | 处置 |
|---|--------|------|------|------|
| 1 | 使用「Murdle / 妙探寻凶」作为游戏名、简介、关键词、分享文案 | 代码里已有「类 Murdle」表述（`README.md:3`、`apps/web/index.html:7`、`docs/DESIGN.md:1`） | 🔴 高 | 发布前**全部清除**；名称、简介、截图、分享卡、客服话术一律不出现 Murdle 及其中文名 |
| 2 | 复制原作的案情文本、人物名、线索措辞、插画、封面、版式 | 无。全部为自研词库（`packages/puzzle-core/src/theme.ts`：雾岭庄园/环轨空间站…）+ 模板生成 | 🟢 低 | 保持；新主题词库继续原创 |
| 3 | 玩法机制雷同（逻辑网格 + 凶案推理） | 相同 | 🟢 低 | 无需处置（规则/玩法不受著作权保护） |
| 4 | 视觉风格（手绘侦探笔记） | 通用风格 | 🟡 中低 | 不要 1:1 复刻书内跨页版式、贴纸、字体排印；自建视觉规范 |
| 5 | 第三方字体/音效/图标未授权 | 暂未引入 | 🟡 中 | 字体用思源黑体/霞鹜文楷（OFL）；音效 CC0 或自录；图标自绘 |
| 6 | 自有名称「疑案簿」被他人抢注 | 未检索 | 🟡 中 | 上线前做 9 类（软件）/41 类（在线游戏）商标检索，预算允许即申请 |
| 7 | AI 生成内容标识义务 | 未使用 LLM，纯模板生成 | 🟢 低 | 若二期引入 LLM 写案情，需按《人工智能生成合成内容标识办法》添加标识 |
| 8 | 内容尺度（凶案题材） | 文案偏「谜案」，无血腥描写 | 🟡 中 | 提审前逐条审文案：去掉尸体、血迹、凶残细节，统一「失窃/失踪/谜案」表述 |

### 3.2 法律依据（为什么这么判）

1. **思想/表达二分法**：著作权保护的是对思想的**表达**，不保护思想、玩法规则、算法本身。逻辑网格题（zebra puzzle / Einstein puzzle）可上溯到 1960 年代的杂志谜题，属于**公有领域玩法类型**。「在 N×N 网格里用排除法推唯一解」这个机制本身无法被任何人垄断。
2. **但表达受保护**：具体案情叙述、人物设定、线索的原句措辞、插画、封面设计、书名，以及**关卡选集的编排**（可能构成汇编作品）都受保护。因此「换皮不换字」是红线——我们的内容全部程序生成 + 原创词库，天然规避。
3. **商标与不正当竞争才是真风险**：Murdle 是 G. T. Karber 的在售商业品牌（图书系列、桌游、murdle.com 每日题），中文市场以《妙探寻凶》发行。即便其在中国大陆的商标注册状态需另行核实，作为**有一定影响的在先使用标识**，仍受《反不正当竞争法》第 6 条（擅自使用与他人有一定影响的商品名称等近似标识、引人误认）约束。在**游戏名、图标、截图、ASO 关键词、分享文案**里蹭这个词，是最容易被投诉下架、也最容易被微信名称审核直接驳回的做法。
4. **平台侧叠加风险**：微信对名称含他人商标的词有拦截；且小游戏备案要求「游戏名称与内容玩法存在关联性」，蹭名牌反而增加驳回。

### 3.3 红线清单（发布前逐条打勾）

- [ ] 仓库内 `README.md`、`apps/web/index.html` 的 meta description、`docs/*.md` 中「类 Murdle」表述：**对外产物必须删除**（仓库内部文档可保留说明，但不得随包分发）
- [ ] 小程序名称、简称、简介、头像、截图、分享标题/图、客服自动回复：零 Murdle 字样
- [ ] 不复制任何原作案情、人物、线索句式、插画、封面、版式
- [ ] 字体/音效/图标：留存授权凭证（OFL / CC0 / 购买发票）
- [ ] 完成「疑案簿」商标检索（9/41 类）
- [ ] 软著申请（虽 IAA 非强制，但备案/维权/融资都需要，建议同期办理）

### 3.4 结论

> **可以放心做，但必须改名。**
> 玩法与现有内容不构成著作权侵权；唯一的实质性法律风险来自**品牌名与宣传口径**。把「Murdle」从所有对外文案中清除、以「疑案簿 / 雾岭谜案」独立品牌运营，风险即可降到可接受水平。平台资质（备案）才是真正的进度瓶颈，不是版权。

## 4. 技术方案

### 4.1 架构

```
┌──────────────────────────────────────────────┐
│  小游戏运行时（无 DOM，仅 Canvas 2D + wx API）  │
│                                              │
│  game.js / main.js  ──►  SceneManager        │
│                          ├─ HomeScene        │
│                          ├─ CampaignScene    │
│                          ├─ GameScene   ◄──┐ │
│                          └─ ResultScene    │ │
│                                            │ │
│  ui/  canvas 组件：Text / Button / Modal    │ │
│       GridView / ClueList / Hud             │ │
│                                            │ │
│  core/ (打包自 packages/puzzle-core)  ──────┘ │
│  platform/  storage / share / ad / haptics    │
└──────────────────────────────────────────────┘
```

- **不做跨端框架**：Taro/uni-app 编译目标是 WXML 小程序，不产出小游戏包；React 19 + Tailwind 4 在 WXSS 下不可用。强行抽象只会增加一层无法调试的中间层。
- **渲染**：单 Canvas，`devicePixelRatio` 缩放；场景栈 + 脏矩形重绘（网格区域局部重绘，避免整屏 60fps 全量 draw）。
- **文本排版**：自研 `wrapText()`（中文按字断行、英文按词、`measureText` 结果按字号缓存），这是 Canvas UI 的主要工作量，预估 300–400 行。
- **交互**：`touchstart/move/end` → 命中测试（矩形数组，倒序）；长按判定 400–500ms；点按循环 ✓ → ✗ → 空；滑动滚动带惯性（可选）。

### 4.2 引擎移植

| 事项 | 方案 |
|------|------|
| 打包 | esbuild 单文件输出（IIFE 或 CJS），产物约 60–90KB；小游戏支持 ES Module 但保守起见用 CJS |
| 生成耗时 | Web 端实测 p95：easy 10ms / medium 167ms / hard 380ms / K4N5 400ms（`docs/DESIGN.md` §7.1）。真机预计 2–4×，hard 档 1–1.5s |
| 对策 1 | 开局前在「载入中」态生成，配进度动画；不阻塞首屏 |
| 对策 2 | `wx.createWorker` 把生成放到 Worker，主线程不卡顿（Worker 内不能直接复用 TS，需单独打一份包） |
| 对策 3 | 关卡模式**构建期预生成**并随包分发（每关 2–4KB JSON，100 关 ≈ 300KB，主包放得下），端上只生成每日题 |
| 每日题 | `dailyPuzzle(\`casefile:${YYYY-MM-DD}\`)`，端上确定性生成 → 全员同题，**无需后端** |
| 一致性验证 | 新增测试：同一 seed 在 Node 与小游戏环境产出的 `Puzzle` 做 JSON 深比较（防止 Math 实现差异） |

### 4.3 数据与存档

```
wx.setStorageSync('casefile:progress:v1', { levels: {...}, daily: {...}, settings: {...} })
wx.setStorageSync('casefile:session:v1',  { seed, marks, hearts, hintsUsed, elapsedMs })  // 断点续玩
```

- 只存 `seed + marks`，题目由 seed 重算（省空间、天然一致）
- 单 key 上限 1MB、总量 10MB，远够用
- 提供「清除本地数据」入口（审核项）

### 4.4 平台能力接入

| 能力 | 用途 | 里程碑 |
|------|------|--------|
| `wx.onShareAppMessage` / `wx.shareAppMessage` | 每日题成绩分享（Canvas 生成海报） | M4 |
| 开放数据域 + 排行榜 | 好友榜（可选） | M5（可砍） |
| 激励视频广告 | 看广告得提示 / 复活 | M4 |
| 插屏广告 | 结算后 | M4（需流量主开通，通常要累计用户达门槛） |
| 震动反馈 `wx.vibrateShort` | 打 ✓/✗、扣心 | M3 |
| 实名认证 / 防沉迷 / 适龄提示 | 合规必备 | M5 |

### 4.5 适配要点

- 安全区：`wx.getSystemInfoSync().safeArea` + 底部手势区留白
- 高 DPR：Canvas 逻辑坐标 vs 物理像素分离，避免网格线发虚
- 小屏（iPhone SE 级 320pt）：N=6 时三个子网格无法并排 → 沿用 Web 的 Tab 切换方案
- 冷启动：主包体积控制在 1MB 内，首屏 < 1.5s

## 5. 里程碑计划

> 单人工时估算，单位：人日。合规线（备案）与开发线并行。

### M0 · 合规先行（第 1 周，5 人日，关键路径）

| 任务 | 产出 | 验收 |
|------|------|------|
| 定名 | 「疑案簿」或备选 3 个，避开 Murdle/妙探寻凶 | 名称查重 + 商标初检通过 |
| 主体选择 | 个人主体（可做休闲 IAA，不可选角色/牌类）或企业主体 | 明确收款/发票/流量主路径 |
| 注册小游戏账号 | 一级类目「游戏」、二级「休闲」 | 后台类目生效 |
| 清理品牌字样 | 删除对外产物中的 Murdle 表述 | `grep -ri murdle dist/` 为空 |
| 提交小游戏备案 | 名称、玩法说明、截图 | 进入「主管部门审核中」 |

> ⚠️ 备案 10–20 工作日且期间不可改名 —— **第 1 周必须启动**。

### M1 · 引擎移植（第 2 周，5 人日）

- esbuild 打包 `puzzle-core` → 小游戏可加载
- 真机 benchmark（低端安卓 / iPhone 12 各一）
- 新增「跨环境同 seed 同题」一致性测试
- 预生成 100 关关卡 JSON（构建脚本）
- **验收**：真机生成 4 档难度各 50 题无异常；同 seed 与 Node 结果完全一致

### M2 · 渲染与交互层（第 3–4 周，10 人日）

- Canvas UI 基础件：Text（换行/缓存）、Button、Modal、ScrollList、Toast
- 网格组件：三子网格 Tab、✓/✗ 循环、长按直打 ✗、自动推论半透明标记、矛盾高亮
- 线索列表：可划线、折叠、字号自适应
- HUD：心数、计时、提示按钮
- **验收**：N=4/5/6 三档在 iPhone SE 与小屏安卓上文字不溢出、点击命中准确、滚动 60fps

### M3 · 玩法闭环（第 5 周，6 人日）

- 关卡选择页（章节解锁、星级展示）
- 游戏流程：开场剧情 → 推理 → 指控 → 结算
- 提示（调 `getHint`，高亮 + 扣分）
- 存档 / 断点续玩 / 设置（关闭自动推论、音效、清档）
- **验收**：冷启动恢复未完成对局；完整玩通 3 关；杀进程不丢档

### M4 · 平台能力（第 6 周，6 人日）

- 每日题入口 + 分享海报
- 激励视频（提示/复活）、结算插屏
- 隐私授权弹窗、用户隐私保护指引、适龄提示
- **验收**：分享卡片可拉起、广告位不遮挡操作

### M5 · 提审上线（第 7 周，3 人日）

- 体验版走查、性能面板自测（启动耗时 / FPS / 内存）
- 提审材料：玩法说明、截图、录屏
- 灰度发布 + 数据埋点（留存/关卡流失点）
- **验收**：审核通过，正式版可搜索进入

**总工期：30 人日 ≈ 6 周**（M0 与后续并行则关键路径约 6 周；若备案顺利）。
